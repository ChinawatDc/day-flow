# แผนจนถึง V1.0.0

เอกสารวางแผนจน tag `v1.0.0`

งานโค้ดคลื่น V0.2–V0.5 ลงมือก้อนเดียวที่ [02-v1.0.0](./02-v1.0.0/) — **บ้านแอป = วันนี้**, ตัวพิมพ์ = Anuphan. เกต «รอใช้จริง 7 วันก่อน V0.2» ข้ามสำหรับโค้ด; Evidence ใช้จริงยังเป็น human ก่อนเรียก 1.0 จริง

แผนปิด V0.1.0 อยู่ที่ [VERSIONS.md](./VERSIONS.md) และ [01-v0.1.0](./01-v0.1.0/)

## นิยาม V1.0.0

สมุดบ้านสำหรับ **ผู้ใช้คนเดียว** ใช้บนมือถือทุกวันได้อย่างมั่นใจ:

- จด จัด แก้ ค้น ลบ ได้ครบ 7 โมดูล
- ไฟล์ใบเสร็จ/เอกสารเปิดได้ เฉพาะผ่านแอป
- เห็นงบเดือนและของใกล้หมดอายุโดยไม่ต้องเปิดชีต
- สำรองข้อมูลตัวเองออกมาได้
- ขึ้น production แล้วใช้ต่อเนื่องโดยไม่พังซ้ำเรื่อง auth / env / schema
- ตัวพิมพ์เป็นระบบเดียวกันทั้งแอป โทน**น่ารักแบบสมุดบ้าน** หัวไทยอ่านชัด ตัวเลขเงินไม่กระโดด
- ทั้ง 7 โมดูลรู้สึกเป็น**สมุดใบเดียว** ไม่ใช่แอปคนละตัวที่สลับกันด้วยเมนู

ยังเป็นเว็บพอร์ทัล (PWA) คนเดียว ไม่ใช่แอปครอบครัว และไม่มี AI

## ปัญหาที่รับแล้ว (จากของ V0.1)

ใช้ได้ในแง่ CRUD แต่**ใช้ยาก** เพราะโครงสร้างเป็นไซโล:

- แต่ละโมดูลเป็นหน้าคนละใบ ฟอร์ม/รายการ/ปุ่มคนละแบบ ไม่มีชุด UI ร่วม
- ฮับเป็นแค่กระเบื้องเมนู วันนี้เป็นสรุปอ่านอย่างเดียว จดด่วนจัดของแล้วจบ — ไม่มีแกน «เปิดแล้วทำต่อได้»
- มือถือซ่อนงาน คลัง บ้าน บันทึก ไว้ในแท็บ «อื่นๆ» ต้องจำว่าของอยู่ห้องไหน
- ตัวพิมพ์ยังไม่น่ารักและไม่เป็นระบบ: Cabinet Grotesk โทนแดชบอร์ดละติน **ไม่มีกลีบไทย** หัวไทยจึงตกฟอนต์สำรอง

แผนหลัง 0.1 จึงเริ่มที่ **จัดหน้าตาและแกนใช้งานทั้งระบบ** ก่อนฟีเจอร์งบ/ค้นหากองใหญ่

## หลักการ

1. คลื่นละ **หนึ่งผลลัพธ์ที่ผู้ใช้รู้สึกได้** ไม่ปล่อยกองฟีเจอร์
2. Must ก่อน Should — ของที่ทำให้เลิกใช้สำคัญกว่าของที่ดูครบ
3. Schema เปลี่ยนเมื่อจำเป็นเท่านั้น และต้องมีวิธี apply บน Neon ชัดเจน (`db:push` / SQL)
4. มือถือ 375 เป็นหน้าหลัก เดสก์ท็อปต้องไม่ถอยจาก V0.1
5. **สมุดใบเดียว** — โมดูลเป็นบทในเล่มเดียวกัน (token, แถวรายการ, ฟอร์ม, CTA) ไม่ใช่ผลิตภัณฑ์ย่อย
6. ตัวพิมพ์โทนน่ารัก อุ่น กลม อ่านไทยได้เป็นหลัก — ไม่ใช้ grotesk ละตินเป็นหน้าตาหัวไทย
7. หลังแต่ละ minor: อัปเดต `docs/acceptance.md` เฉพาะเกณฑ์คลื่นนั้น แล้ว tag ตาม [BRANCHING.md](./BRANCHING.md)

## V0.2.0 — สมุดใบเดียว (UX/UI ทั้งระบบ + ตัวพิมพ์น่ารัก)

ผู้ใช้เปิดแอปแล้วรู้ว่าอยู่หน้าไหน ทำอะไรต่อได้ และรู้สึกเป็นสมุดบ้าน ไม่ใช่ 7 แอปสลับเมนู

ทำ **ก่อน** ค้นหา/งบเดือน — ถ้าหน้าตายังคนละใบ ฟีเจอร์ใหม่จะยิ่งเพิ่มไซโล

ลำดับในคลื่นนี้: (ก) ระบบภาพและตัวพิมพ์ → (ข) ชุดคอมโพเนนต์ร่วม → (ค) แกนนำทางและไหลข้ามโมดูล — อย่าไล่ตกแต่งทีละหน้าโดยไม่มี token

### ของที่เป็นปัญหาตอน V0.1

- ฮับ = เมนูกระเบื้อง, วันนี้ = อ่านสรุป, จดด่วน = จัดของแล้วจบ, โมดูลอื่น = CRUD คนละฟอร์ม
- แท็บล่างมีแค่ ฮับ / วันนี้ / จด / เงิน — ที่เหลืออยู่ใน «อื่นๆ»
- ไม่มีแถวรายการ/สถานะว่าง/ปุ่มหลักร่วม
- Cabinet Grotesk เป็นหัวแต่ไม่มีไทย และโทนไม่น่ารักแบบสมุด

### In scope

1. **ระบบตัวพิมพ์โทนน่ารัก** — ทั้งระบบ ไม่ใช่เปลี่ยนไฟล์ฟอนต์อย่างเดียว
2. **ระบบ UI ร่วม** — แถวรายการ, การ์ดสรุป, ฟอร์ม, ปุ่มหลัก/รอง, สถานะว่าง, แนบไฟล์ ใช้ชุดเดียวกันทุกโมดูล
3. **แกนใช้งาน** — วันนี้ (หรือจดด่วน) เป็นบ้าน; โมดูลเป็นบท ไม่ใช่ทางตัน; ลดการซ่อนโมดูลใน «อื่นๆ»
4. **ไหลข้ามโมดูล** — จากวันนี้/จด ไปปิดงาน จ่ายเงิน เปิดคลัง โดยไม่หลงว่ากลับยังไง (คงบริบทหรือมีทางกลับชัด)

### ก) ระบบตัวพิมพ์ — น่ารักทั้งเล่ม

ใช่ — ทิศทางที่ต้องการคือ **น่ารัก อุ่น กลม เป็นสมุด** ไม่ใช่แดชบอร์ดเทค

**In scope**

- บทบาทให้จบ: `display` · `title` (หัวไทย) · `body` · `caption` · `numeric`
- token `--font-*` `--text-*` `--leading-*` แล้วหน้าใช้คลาสบทบาท ไม่โปรย `text-4xl` / `font-display`
- **หัวและเนื้อไทย** ครอบครัวที่รองรับไทย โทนมน น่ารัก อ่านบนมือถือชัด (เลือกตอนลงมือ เช่น Anuphan หนา, Mali, หรือครอบครัวไทยมนอื่นที่ไลเซนส์ใช้ได้ — ต้องลองบน 375)
- **ตัวเลขเงิน** tabular ครอบครัวเดียวทั้งแอป; ละตินคำว่า `day-flow` จะใช้ฟอนต์แบรนด์หรือใช้ชุดไทยมนคู่ละตินก็ได้ **ถ้าไม่ทำให้หัวไทยดูเป็นคนละแอป**
- Cabinet Grotesk **ไม่บังคับคงไว้** ถ้ายังดูเป็นแดชบอร์ด — เอาออกจากหัวไทยได้เลย; เก็บเป็น numeric ได้เฉพาะเมื่อเข้ากับโทนใหม่
- น้ำหนักที่มีไฟล์จริงเท่านั้น ไม่สังเคราะห์
- ไล่ login / ฮับ / วันนี้ / เงิน / งาน ให้สเกลเดียวกัน
- จดตาราง token ใน [architecture.md](./architecture.md) เมื่อลงมือ
- screenshot 375/768/1440 เทียบชุดเดิม

**Out of scope (ตัวพิมพ์)**

- ให้ผู้ใช้เลือกฟอนต์ในตั้งค่า
- ธีมมืด (Should ของ V1.0)
- ซื้อฟอนต์ถ้าของฟรี/ที่มีอยู่จัดโทนน่ารักได้

### ข) ระบบ UI ร่วม

- หนึ่งแพทเทิร์นรายการ: ชื่อ · คำอธิบายหนึ่งบรรทัด · ค่า (เงิน/วัน) · แอ็กชัน (เสร็จ ลบ เปิด)
- หนึ่งแพทเทิร์นฟอร์ม: เลเบล · อินพุต · แนบไฟล์ · ปุ่มบันทึกเต็มความกว้างมือถือ
- สถานะว่างข้อความสั้น + CTA เดียว
- ระยะ รัศมี การ์ด สีกระดาษ/หมึกใช้ token ชุดเดียว — ปรับโทนให้อุ่นขึ้นได้ถ้าตัวพิมพ์น่ารักแล้วยังดูแข็ง (ไม่เปลี่ยนแบรนด์สีทั้งก้อนโดยไม่มีเหตุ)
- ไอคอนสไตล์เดียวกัน (ไม่ปนคม/กลมโดยไม่มีกติกา)

### ค) แกนนำทาง — เลิกไซโล

**บ้านของแอป: วันนี้** (`/today`). ฮับยุบเป็น `/menu`. ตัวพิมพ์ทั้งเล่มเป็น Anuphan (ไม่มี Cabinet เป็นหัวไทย)

จากนั้น:

- แท็บล่างมือถือสะท้อนงานที่ทำทุกวัน ไม่ซ่อนครึ่งสมุดใน «อื่นๆ» โดยไม่มีทางลัดจากวันนี้
- จากสรุปวันนี้ กดตัวเลข/งาน/inbox แล้ว**ทำต่อในบริบทนั้นได้** ไม่ใช่แค่ลิงก์ไปหน้าเปล่า
- จดด่วนจัดเข้าโมดูลแล้วยังเห็นของที่เพิ่งจัด หรือกลับวันนี้ได้โดยไม่เริ่มจากศูนย์
- เดสก์ท็อป rail ยังครบโมดูล แต่เนื้อหาใช้ชุด UI เดียวกับมือถือ ไม่ใช่ตารางคนละภาษาภาพกับมือถือ

ไม่รวมในคลื่นนี้: รวม 7 โมดูลเป็นหน้าเดียวแบบ infinity scroll, ลบโมดูลทิ้ง, ครอบครัว

### Out of scope (คลื่นนี้ทั้งก้อน)

ค้นหาเต็มระบบ, สรุปงบหลายหมวดแบบหน้าใหม่, กราฟ, OCR, push, ตัวเลือกฟอนต์, รีไรต์สแต็ก (ยัง Next.js)

ค้นหา + สรุปเงินเดือน + กรองคลังหมดอายุ ไป **V0.3** ให้ทับชุด UI ใหม่

### User flows (เป้าหลัง V0.2)

1. เปิดแอป → อยู่บ้าน (วันนี้หรือจด) → เห็นของที่ต้องทำวันนี้ → กดปิดงานหรือจดรายจ่ายได้ในไม่กี่ tap
2. จดข้อความ → จัดเป็นงานหรือเงิน → รู้ว่าไปอยู่บทไหน โดยไม่ต้องเปิดฮับ
3. สลับบทงาน/เงิน/คลัง/บ้าน/บันทึก แล้วรายการกับฟอร์มหน้าตาเดียวกัน
4. อ่านหัวไทยแล้วรู้สึกเป็นสมุด ไม่ใช่ SaaS

### Data / schema

- คลื่นนี้ไม่บังคับตารางใหม่
- ถ้าเปลี่ยนบ้านแอป เป็นเรื่องเส้นทาง/เลย์เอาต์ ไม่ย้ายตาราง

### Test plan

- [ ] มือถือ 375: จากเปิดแอปถึงจดรายจ่ายหรือติ๊กงาน ไม่เกินเส้นทางที่ล็อกในแผนฟีเจอร์ (เขียนจำนวน tap ตอนลงมือ)
- [ ] งาน เงิน คลัง บ้าน บันทึก ใช้แถวรายการและฟอร์มชุดเดียวกัน (ตรวจด้วยตา + screenshot)
- [ ] ไม่มีโมดูลที่เข้าแล้วไม่มีทางกลับบ้านชัด
- [ ] DevTools: หัวไทย computed font รองรับไทย และไม่ใช่ Inter / Times เป็นหลัก
- [ ] ยอด ฿ tabular ครอบครัวเดียว วันนี้กับเงิน

### In scope

1. **แก้ไข** งาน เงิน คลัง ของในบ้าน รายการซื้อ บิล จดด่วน บันทึกวัน (ฟิลด์หลักที่สร้างได้) — ฟอร์มชุดเดียวกับ V0.2
2. **ยืนยันก่อนลบ** รายการที่มีไฟล์ ลบ object R2 ตามของเดิม
3. **ค้นหา** กล่องเดียวจากบ้านแอป กรองงาน / เงิน / คลัง / จดที่ยังไม่จัด
4. **เงินเดือนนี้** สรุปตามหมวด + ยอดรวม (ยังไม่บังคับตั้งเพดานงบ)
5. **คลังใกล้หมดอายุ** หน้ารวมหรือตัวกรอง จากที่วันนี้เตือนอยู่แล้ว
6. **ส่งออก** JSON (ครบ) และ CSV เงิน+งาน อย่างน้อย
7. **บัญชี** เปลี่ยนรหัสผ่าน

### Out of scope

นำเข้ากลับ (import), sync ข้ามเครื่องแบบ CRDT, ลบบัญชีถาวร (V0.5), กราฟ, OCR

### User flows

1. เปิดรายการ → แก้ → บันทึก → วันนี้/สรุปเงินสะท้อนค่าใหม่
2. จากบ้านแอป ค้นคำ → เปิดรายการต้นทาง
3. เปิดเงิน → เห็นยอดเดือนนี้แยกหมวด
4. ตั้งค่าหรือฮับ → ส่งออก → ได้ไฟล์ดาวน์โหลด
5. เปลี่ยนรหัส → ออกจากระบบ → เข้าด้วยรหัสใหม่ได้

### Data / schema

- ไม่บังคับตารางใหม่ ยกเว้นถ้าต้องเก็บ `updated_at` ให้ครบทุกโมดูล
- ค้นจากคอลัมน์ที่มีอยู่ ไม่ต้อง full-text ถ้ายังไม่จำเป็น
- export อ่านจาก DB ของ session user เท่านั้น

### Test plan

- [ ] แก้จำนวนเงินแล้วสรุปเดือนเปลี่ยน
- [ ] ลบรายการที่มีใบเสร็จ แล้วเปิด `/api/files?key=` ของ key นั้นไม่ได้
- [ ] ค้นเจอเฉพาะของ user ตัวเอง
- [ ] สรุปหมวดเดือนนี้ตรงกับรายการ
- [ ] ของหมดอายุเกิน 30 วันไม่โผล่กลุ่ม «ใกล้หมด»
- [ ] export ไม่มีข้อมูล user อื่น

## V0.4.0 — วันนี้ผลักให้ทำต่อ

หน้าวันนี้ไม่ใช่แค่สรุป แต่ชี้ของที่ค้างจนเลิกเปิดแอป — ใช้แกนบ้านจาก V0.2 ไม่สร้างเลย์เอาต์คนละชุด

### In scope

1. งานค้างข้ามวัน (due ผ่านแล้วยังไม่เสร็จ) แยกจากงานวันนี้

3. Inbox ค้างนาน (เช่น >3 วัน) โชว์ชัด

### User flows

2. บ้าน → คัดลอกบิลเดือนที่แล้ว → รายการเดือนนี้โผล่สถานะยังไม่จ่าย

### Test plan

- [ ] คัดลอกบิลไม่ซ้ำของเดิมในเดือนเดียวกันถ้ากดสองครั้ง (กำหนดกติกาแล้วล็อกในแผนฟีเจอร์)

## V0.5.0 — ทนพอเป็นหนึ่งจุดศูนย์

ผู้ใช้ไม่ต้องรู้เรื่อง Neon/R2 และผู้ดูแลรู้เมื่อระบบพัง

### In scope

1. **ลบบัญชี** (ลบแถว user cascade + object ใน R2 ที่ขึ้นต้น `userId/`)
2. **health** แยก db / r2 / auth env ชัดเจน (อย่า leak secret)
3. **schema ทางการ** เอกสารว่าจะ `db:push` ต่อหรือเริ่ม migrate ที่ snapshot ไม่ว่าง
4. **observability เบา** — อย่างน้อย log ที่ Vercel + หน้า error ที่อ่านรู้เรื่อง (Sentry เป็น Should ไม่ใช่ Must)
5. Playwright ครอบ login + สร้างงาน + สร้างรายจ่าย (ไม่ใช่แค่ screenshot)

### Out of scope

multi-tenant, billing, Slack on-call, Edge rewrite ใหญ่

### Test plan

- [ ] ลบบัญชีแล้วสมัครเมลเดิมได้ หรือเมลถูกปล่อยตามที่กำหนดในแผน
- [ ] เทส e2e เขียวบน CI หรือสคริปต์ที่รันก่อน tag
- [ ] `/preview` ยัง 404 บน production
